# AURELIA WAR BOT v1.4.4 — компактный текст и внешний край панели

Полный проект в одной папке. Python 3.11+, aiogram, NumPy/OpenCV и FFmpeg.
В этой версии меняется оформление, а механики v1.2 и сохраненные войны остаются прежними.

## Быстрый запуск и обновление

1. Распакуйте файлы рядом с `run.py`, без вложенных каталогов.
2. Выполните `pip install -r requirements.txt`.
3. Создайте `.env` по `.env.example`, вставьте `BOT_TOKEN`; при необходимости укажите свой `OWNER_ID`.
4. Запустите `python run.py`. На хостинге указывайте **run.py** строчными буквами.
5. `/demo` создаёт новую войну с 28.06.2057. Команда заменяет текущую войну.

При обновлении существующего бота сохраните свою `.env` и `war_state.sqlite3`:
заменяйте код и постоянные assets, затем перезапустите процесс. Тестовые
`example_state.sqlite3` и `cinematic_state.sqlite3` не являются вашей живой войной.
Для удобства можно перед обновлением скопировать свой файл SQLite отдельным файлом.
Новые таблицы добавляются автоматически в тот же SQLite, миграция журналов не нужна.

## Интерфейс видео

- Плоская темная панель, цвет **#A9F38F**, предоставленный **Isaac.ttf**.
  Сохранены компактные отступы и строки. Тонкая мятная линия идет по
  внешнему краю боковой панели у карты. Отдельная рамка вокруг текста убрана.
  Название войны, дата, номер дня и последние захваты. Проценты контроля,
  оккупации и серой зоны, счетчики городов и нижняя подпись убраны из видео.
  Полная игровая статистика доступна через `/status`.
- Без скругленных карточек, VS, дублирующей миникарты и расходящихся колец.
  На карте захват обозначается маленьким мятным квадратом и названием;
  фон подписи имеет около 45% непрозрачности; текст города на 45% прозрачен
  (55% непрозрачности) и плавно появляется/исчезает;
  подпись плавно появляется и исчезает за 2.2 секунды. Последние четыре
  смены контроля остаются в левой панели, с именем, стороной и датой.
- При тесном скоплении города остаются отмечены, а подписи размещаются в
  свободных позициях. Если свободного места нет, имя остается в списке
  последних событий, без перекрывающей соседей большой плашки.
- Реальные имена берутся из **settlements.json**: полный предоставленный
  реестр из 369 населенных пунктов на карте 4096×3072. Совпадение с маркером
  определяется по координатам с допуском 8 исходных пикселей; номер компоненты
  PNG не используется для выбора имени. В текущем слое именованы 278 из 345
  маркеров; северные маркеры вне области каталога обозначаются «Без названия».
  Все 70 захватов тестовой 60-дневной войны имеют настоящие имена из JSON.
- Замена/исправление имен в JSON учитывается при `/rerender` и `/preview`
  сразу, в том числе для старого кеша v1.4. Дельты фронта и журнал не меняются.
  Для другой карты предоставьте реестр с ее исходными width/height и списком
  all_places из объектов name/x/y. Автоматического масштабирования координат нет.
- Импульс наступления показывает только действительно изменившуюся территорию.
- Цветокоррекция, умеренная резкость и качественное масштабирование карты
  выполняются отдельно от UI. В 4K детали карты берутся из исходного разрешения.
  Постобработка включает сглаживание мелкой текстуры с сохранением границ,
  умеренный контраст и насыщенность, локальную детализацию рельефа и резкость.
  Она применяется и к `/map` / `/map4k`; `/effects postprocess off` отключает ее.
  Во время подготовленного хода оформление карты фиксируется вместе с эталоном,
  чтобы переключение эффекта не ломало проверку свежести разметки.

## Команды оформления и экспорта

| Команда | Результат |
|---|---|
| `/preview` | Новый UI-кадр 1920×1080 для просмотра |
| `/effects` | Кнопки эффектов: уведомления, города, наступления, постобработка, изгиб |
| `/effects notifications off` | Отключить уведомления; аналогично `city_glow`, `attack_glow`, `postprocess`, `curved` |
| `/effects seconds_per_day 0.4` | Темп cinematic: 0.1–3 секунды на игровой день |
| `/effects crf 18` | H.264 CRF 14–26; меньше число — выше качество и размер файла |
| `/effects reset` | Вернуть настройки по умолчанию |
| `/exportcinema 30 1920` | Многокадровое видео с полноценной анимацией |
| `/exportcinema 30 3840` | Cinematic 4K, 3840×2160 |
| `/rerender 30 1920` | Повторный cinematic рендер с текущими эффектами |
| `/export 30 1920` | Новый UI, но прежний ритм: старт + один кадр на день |
| `/export4k 30` | Тот же подневный режим шириной 3840 |
| `/exportcurve 30 1920` | Подневный режим с мягким изгибом карты |

Видеокадры теперь **16:9**: 1920×1080 / 3840×2160; карта помещается целиком,
без обрезки. `/map` и `/map4k` сохраняют привычное соотношение сторон карты.
Приказы по-прежнему рисуйте только на свежем **/map**, а не на `/preview`.
Розовый Кефирстана: **#FF00FF**; зелёный Йогуртстана: **#00FF66**.
Отправляйте размеченный PNG как документ, без сжатия. `/turn 30 100` — обе стороны;
`/attack kefir 30 100` или `/attack yogurt 30 100` — одна сторона.

Cinematic удерживает старт 1 секунду, каждый игровой день — заданное число
кадров, финал — 2.2 секунды для завершения анимаций. При 30 FPS и 0.4 с/день
60 дней дают **816 кадров / 27.2 секунды**, при этом симуляция содержит ровно 60 дней.
В подневном экспорте те же 60 дней дают **61 кадр**. Длительность дня округляется
до целого количества кадров. Маркеры вне территории не считаются городами.

Все MP4: H.264, yuv420p, `faststart`, CRF по настройке и preset medium.
FFmpeg берется из PATH или поставляется через `imageio-ffmpeg`.
Размер отправки через Telegram ограничен 49 MB; для больших видео уменьшите ширину
или повысите CRF. Прогресс расчета, рендера кадров и завершения кодирования сохраняется.

Кнопка **Метки городов** управляет компактными квадратами. Ключ `city_glow`
сохранен для совместимости старых настроек и команд; свечение и кольца убраны.
Уведомления управляют именами на карте и списком последних смен контроля.

## Повторный рендер без изменения войны

Первый экспорт строит визуальную временную линию read-only replay журнала.
Затем она хранится в **том же SQLite** как сжатые разреженные изменения control,
contested и fresh-capture плюс события городов. Полные ежедневные PNG не хранятся.
Повторный `/rerender` или экспорт использует этот кеш, не вызывая движок симуляции.
Изменение эффектов не меняет дату, control, homeland, операции, seed и физические слои.
После нового хода, изменения слоя, `/undo` или `/demo` кеш пересобирается по журналу.
Контрольные суммы позволяют восстановить поврежденный визуальный кеш.
`/doctor` по-прежнему проверяет и исправляет основное состояние войны.

# Aurelia — Telegram-бот подневного фронта

Python 3.11+, aiogram 3. Один плоский каталог, один рабочий SQLite-файл для всех чатов и всей истории. Карты, код и примеры находятся рядом. Вложенные каталоги для работы бота не нужны и не создаются. Симуляция всегда работает в исходных пикселях.

## Запуск

1. Установите Python 3.11 или новее.
2. Для запуска и экспорта достаточно зависимостей из requirements.txt: imageio-ffmpeg включает готовый FFmpeg для обычных Windows/Linux/macOS. Системный FFmpeg также поддерживается. Для расширенных тестов с ffprobe установите системный FFmpeg; на Debian/Ubuntu: `sudo apt install ffmpeg`.
3. Распакуйте все файлы ZIP в один каталог.
4. В этом каталоге выполните:

```sh
pip install -r requirements.txt
```

5. Скопируйте `.env.example` в `.env`, откройте обычным текстовым редактором:

```ini
BOT_TOKEN=123456789:токен_полученный_у_BotFather
OWNER_ID=ваш_числовой_Telegram_ID
DATA_FILE=war_state.sqlite3
```

`OWNER_ID` необязателен: пустое значение или 0 разрешает всем пользователям обращаться к боту; войны разделены по chat_id. Если ID задан, все команды и загрузки доступны только этому пользователю. В групповом чате война одна на чат. Токен не отправляйте в чат и не публикуйте. Не запускайте два экземпляра с одним токеном одновременно.

6. Проверьте файлы без подключения Telegram:

```sh
python run.py --self-check
```

7. Запустите:

```sh
python run.py
```

Папка с проектом может быть любой: `.env`, карты и БД ищутся рядом с `run.py`, независимо от текущего рабочего каталога. Ручное выставление environment variables не нужно. Бот должен оставаться запущенным на компьютере или сервере; закрытие процесса прекращает прием команд. В архиве нет чужого токена; живое соединение с вашим ботом начинается после заполнения `.env`.

## Bothost и другие хостинги с автовыбором запуска

В настройках Bothost: «Дополнительные настройки» → «Главный файл (точка входа)» → `run.py`, затем новый деплой. В этом исправленном архиве также есть `main.py`, который запускает ту же программу автоматически. Прямой `python bot.py` теперь тоже запускает polling. Токен, заданный хостингом в BOT_TOKEN, принимается без файла .env; локальный .env по-прежнему поддерживается.

Логи должны сначала показать `Aurelia: launcher started; loading bot libraries...`, а затем сообщения aiogram о polling или конкретную ошибку. Версия v1 без исправления при автовыборе `bot.py` могла молча завершаться: это исправлено, формулы движка и данные войны не менялись.

## Первый ход

В Telegram откройте бота:

```text
/demo
/turn 30 100
```

`/demo` заменяет текущую войну этого чата и начинает ее 28.06.2057 с готовыми дорогами, рельефом и городами. Команда хода присылает НОВЫЙ исходный PNG с идентификатором приказа. Можно повторно взять его через `/map`.

Скачайте PNG и рисуйте на нем линии толщиной 3–8 px:

| Сторона | Цвет приказа |
|---|---|
| Кефирстан | `#FF00FF` |
| Йогуртстан | `#00FF66` |

Начало линии должно лежать на своей контролируемой территории либо в пределах 8–20 px от нее. Конец указывает направление противника. Можно рисовать горизонтальные, вертикальные, диагональные, кривые, S-образные линии и несколько отдельных линий. Замкнутые петли не принимаются; пересекающиеся линии лучше разделить. Не рисуйте стрелочные наконечники с несколькими ветками: нужна сама траектория.

Верните PNG как **документ/файл без сжатия**. Не отправляйте как Telegram-фотографию. Не меняйте разрешение, палитру, фон, подписи или рельеф. Старый кадр, JPEG, чужой цвет стороны в односторонней атаке и измененный фон отклоняются. Штамп карты различает даже ходы ожидания, когда сама территория не менялась. После ошибки ожидание загрузки сохраняется: можно исправить PNG и отправить снова.

`WIDTH` — примерный оперативный масштаб в пикселях оригинала, а не радиус жесткой кисти. Нарисованная длина — намерение: тяжелый участок может остаться недостигнутым к концу операции. Линии приказа никогда не попадают в результат.

Для одностороннего хода:

```text
/attack kefir 30 100
/attack yogurt 15 70
```

`/turn` допускает обе стороны в одном PNG; допустим и приказ только одной стороны. Встречные атаки считаются по общему дневному времени, а не последовательным наложением результатов.

## Стартовая карта и неизменный homeland

| Точный RGB | Homeland | Начальный control |
|---|---|---|
| `#4A0000` | Кефирстан | Кефирстан |
| `#00134A` | Йогуртстан | Йогуртстан |
| `#B12823` | Йогуртстан | Кефирстан |
| `#1F52A6` | Кефирстан | Йогуртстан |

В `/newmap` все другие цвета — непроходимая нетерритория. Вода не становится сушей из-за проходящей по ней дороги. Если на стартовой карте нанесены непрерывные черные линии границы между сторонами, они также будут непроходимыми. homeland и initial_control защищены от записи; контроль меняется отдельно.

**Особенность приложенного исходника.** В `yogurtstan_base_control.png` черная обводка полностью разрывает сухопутный контакт двух сторон: нет ни одного соседства по горизонтали/вертикали. Движение через нее при строгом декодировании невозможно. Поэтому `/demo` использует отдельный `yogurtstan_demo_control.png`: до начала войны 3 164 пикселя тонкой черной обводки в пределах 3 px от ОБОИХ цветов восстановлены по ближайшей стороне. Исходник сохранен без изменения. Реки, озера, фон и внешние границы не перекрашены. Правило и число исправлений записаны в `demo_preparation.json`; подготовку можно воспроизвести командой `python -B prepare_demo.py`. Эта коррекция не выполняется во время войны или при загрузке пользовательской карты.

## Загрузка слоев

После `/newmap` пользовательские слои загружаются отдельно. Каждый слой должен иметь **строго тот же размер**, что стартовая карта; изменение разрешения отклоняется.

```text
/roads
```

После команды отправьте `yogurtstan_roads.png` документом. Принимается прозрачный PNG с линиями дорог либо черно-белая непрозрачная маска, где белое — дороги. Для произвольной непрозрачной карты с фоном сначала подготовьте отдельную маску: бот не угадывает дороги среди подписей и посторонних линий. `yogurtstan_roads_mask.png` также совместим.

Города: `/cities`, затем прозрачный слой. Alpha используется и для визуала, и для механики; если слой содержит подписи, они тоже будут считаться городской маской. Приложенный слой содержит маркеры городов.

Рельеф: `/terrain`, затем исходный PNG. Приложенная карта градационная: темное — равнины, светлое — высокогорье. `config.py` содержит TERRAIN_MODE (`brightness` / `inverse_brightness`), диапазон стоимости и силу визуального смешивания. Для иной цветной физической карты сначала проверьте смысл яркости; автоматическая трактовка не является универсальным распознаванием высот. Настройки физики сохраняются в сессии и журнале: старые ходы не меняют результат после правки config.py.

Слой дорог влияет на стоимость движения и снабжение, включая соседние пиксели, а дорожные узлы — на сопротивление. Дорога не означает автоматический захват. Иконки городов замедляют движение; окруженный городской карман держится 18–30+ дней в зависимости от его размера. Бесгородный карман с полностью вражеским кольцом сдается. Вода, побережье и край карты не считаются полным вражеским кольцом.

В обновленной модели длинная операция выбирает ближайшую связную дорогу, которая идет в сторону приказа и остается внутри его оперативного коридора. Колонны движутся по ней быстрее, а вне дорог можно наступать и расширять фланги с задержкой. Несвязная дорога за водой не становится точкой появления войск. Линия задает направление и масштаб; ширина разных участков заметно меняется, а ее конец не превращается в большой круглый выступ. Локальные темпы тоже различаются: соседние секторы могут прорываться и задерживаться в разные дни.

Серая зона обычного фронта остается 1–2 px. При продолжающихся встречных боях сохраняется отдельный meeting_age. После 18 дней небольшая доля пространственно связанных участков может дать широкую зону 7–10 px. Базовая вероятность выбора участка — 12%; с длительностью она плавно повышается. Это шанс на локальный сектор, а не независимый бросок для каждого пикселя или всего фронта. Без новых встречных боев возраст уменьшается и зона сужается. Настройки: ROAD_PRIORITY, WIDTH_VARIATION, WIDE_BATTLE_DAYS, WIDE_BATTLE_CHANCE.

Существующую войну пересоздавать не нужно. Все старые ходы продолжают использовать прежнюю модель. Со следующим новым ходом (/attack, /turn или /wait) бот автоматически включает новую модель и записывает точные настройки в это событие журнала. /undo отменяет и сам ход, и включение модели. /doctor и экспорт воспроизводят смену правил в тот же день; история до обновления остается прежней.

## Свежие захваты: один дневной кадр

В день изменения контроля новая территория подсвечивается: Кефирстан — `#FFA7A4`, Йогуртстан — `#76ABFF`. Со следующего игрового дня цвет возвращается к обычному цвету контроля или оккупации. Это касается и захвата окруженного кармана, и освобождения собственной территории. Серая зона и города остаются поверх подсветки; рельеф мягко смешивается с ней.

В операции на 30 дней каждый кадр показывает только изменения своего дня, а не все накопленные захваты операции. `/map` и `/map4k` показывают подсветку последнего игрового дня, пока не пройдет следующий день; время Telegram или перезапуск бота ее не сбрасывают. Обычный, curved и 4K экспорты используют ту же дневную маску. Начальный кадр без подсветки.

Старые SQLite-сессии совместимы. Для подсветки последнего дня старой войны после обновления выполните `/doctor` один раз: она будет восстановлена из журнала. Подсветка — только визуальный слой; она не меняет правила движения, homeland, control или игровой календарь.

## Прогресс расчета и рендера

Во время расчета новых дней, создания PNG и экспорта видео бот редактирует одно сообщение с полосой прогресса. Оно показывает процент, число готовых дней/кадров и текущий этап. Обновления — примерно раз в 2 секунды, без отдельного сообщения на каждый день.

Ход на 30 дней показывает 30 расчетных дней. Видео всей войны за 60 дней показывает 61 кадр: стартовый и 60 дневных. Пока FFmpeg завершает файл MP4, прогресс остается на 99%; 100% появляется после успешного завершения. Создание отдельного PNG показывает 3 этапа: загрузка состояния, рендер карты и кодирование PNG. /undo и /doctor тоже показывают повторный расчет по дням. Ошибки редактирования сообщения прогресса не меняют состояние войны.

## Видео

```text
/export 30 1920
/export4k 30
/exportcurve 30 1920
```

Экспортируется вся история текущего чата: один стартовый кадр плюс по кадру на каждый прошедший день. 30 дней дают 31 кадр; 60 дней — 61 кадр. Поэтому 60 дней при 30 FPS длятся около 2 секунд: уменьшите FPS, если хотите медленнее смотреть историю.

Видео: H.264/libx264, yuv420p, faststart, дата на каждом кадре. Curve — только мягкая деформация уже отрисованного RGB, состояние войны не меняется. FFmpeg получает кадры потоково без каталога PNG. Временный MP4 в системном tempfile удаляется после отправки. Для Telegram ограничение отправляемого видео — 49 MB; при превышении уменьшите ширину. Входящие PNG — до 19 MB. Большие экспорты требуют времени; одновременно выполняется один тяжелый расчет, чтобы несколько чатов не исчерпали память.

## Журнал, отмена, надежность

`war_state.sqlite3` создается после запуска с токеном. В нем все чаты, исходные массивы, загруженные слои, операции, семена, боевой возраст, окружения и ожидающие загрузки. Нет отдельного файла или каталога на войну. БД использует транзакции; незавершенная операция не попадает в журнал. Полные ежедневные кадры не хранятся.

История — источник истины. `/undo` отменяет последнее событие, включая загрузку/удаление слоя. `/doctor` пересчитывает историю и проверяет контроль, homeland, боевые поля, дату и слои; поврежденный кеш восстанавливается. Слои записываются событиями, поэтому видео не применяет сегодняшние дороги к старым дням. Исходная PNG-разметка преобразуется в сжатые логические маски приказов.

Случайность детерминирована сохраненным seed. Движение вычисляется один раз в локальной области приказа с помощью компилируемого Dijkstra; подневные пороги используют коррелированный темп. Направление берется из геодезического расстояния вдоль скелета кривой, а не из фиксированной оси. Три масштаба пространственного шума, дороги, рельеф, города, боковая стоимость и снабжение формируют неровный фронт. Обычная серая зона — 1 px; широкие области ограничены встречами, городами и узлами с накопленным возрастом боя. Снабжение проверяется через связь с текущим контролем; полные окружения ищутся через компоненты связности.

Это моделирование сухопутного фронта без численности войск и полноценной экономической логистики. Оно не предсказывает реальные войны. Десанты, разрушение мостов и ракетные удары не создаются автоматически: `/canon` только объясняет фазу хроники, включая направление Новомир — Старовир 11–18.07.2057. Канонное завершение 12.11.2060 не блокирует альтернативную историю.

## Проверки и примеры

```sh
python -B -m pytest -q
python -B smoke_real.py
```

`-B` предотвращает создание `__pycache__` при тестировании; pytest.ini отключает `.pytest_cache`; numba использует JIT без файлового кеша. `python run.py` сам отключает запись bytecode перед импортом модулей. Установка библиотек может создавать их служебные каталоги в Python installation, вне проекта.

Автотесты проверяют линии всех направлений и S-форму, несколько линий, обе стороны, совместный ход, дороги и фланги, проходимость воды/нетерритории, рельеф, локальные долгие бои, окружения, неизменность homeland, цвета оккупации, replay/undo/doctor, транзакционный отказ, свежесть PNG, JPEG/размер/цвет, диспетчер aiogram с подмененным Telegram-транспортом, H.264 и режимы обычный/curve/4K. Реальный Telegram API без токена не вызывается.

`smoke_real.py` воспроизводит 60 дней с 3 операциями на подготовленной реальной карте 4096×3072, проверяет неизменность homeland, непроходимость воды, doctor и отдельные контролируемые сценарии окружений и долгих встречных боев на реальной карте. Последние — искусственные тестовые условия с настоящими слоями городов/дорог, а не заявление, что такие котлы или долгие бои возникли естественно в основной истории. `example_battle_detail.png` относится к отдельной проверке долгого встречного боя.

Приложены `example.mp4`, `example_curved.mp4`, `example_preview.png` (3840 px), промежуточные кадры, детализация фронта, `smoke_report.json` и `validation_report.txt`. Видео дополнительно прочитаны ffprobe и полностью декодированы ffmpeg. Все эти файлы лежат непосредственно в корне.

`example_state.sqlite3` — отдельная воспроизводимая база примера, не рабочая БД бота. Текущая демонстрация в ней записана для chat_id -2057. Не переименовывайте ее в рабочую БД ради доступа из Telegram; для собственной войны используйте `/demo`. Обычные сессии бота всегда хранятся вместе в одном DATA_FILE.

При отсутствии системного FFmpeg экспорт автоматически берет бинарник imageio-ffmpeg; проверка этого пути также входит в тесты. На необычной платформе без готового бинарника потребуется системный FFmpeg.

Ориентир ресурсов: для исходной карты 4096×3072 желательно 4 GB свободной памяти и 64-битный Python. Первый расчет включает компиляцию numba; дальнейшие быстрее. ENGINE_VERSION защищает совместимость формата состояния; FRONT_MODEL выбирает сохраненную версию алгоритма. При дальнейших изменениях формул сохраняйте предыдущие ветки модели, чтобы старые события оставались воспроизводимыми.
